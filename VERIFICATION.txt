今回の変更
・定期支出の自動計上は、同じ設定・同じ対象月に同じ記録IDを使い、
  Firestoreのトランザクションで最新の設定と既存記録を確認します。
・複数人の追加・編集・削除・休止が重なっても、別の変更を消さないようにしました。
  同じ項目の古い編集・確認は保存せず、画面を開き直すよう案内します。
・削除した定期支出の対象月は、再起動後にも再生成しません。
・定期支出のOFFは休止した日を保存し、再開時に休止期間を確定します。
  休止中に計上日を迎えた分は、再開後も自動計上しません。
  再開日が計上日であればその日を対象にします。計上日を過ぎて再開した場合は、
  次の設定済み計上日から記録します。休止前の有効期間の未計上分は補います。
  スイッチ・編集フォームの両方に適用し、複数回の休止期間も保持します。
  旧版でOFFになっていて休止日がない設定は、再開日より前の未計上分を除外します。
・初回読み込みの順序、ログアウト・アカウント切り替え、通信失敗からの再試行を見直しました。
・残高グラフの期間を、Firebaseプロジェクトとログインユーザーごとの
  localStorageに保存します。同じブラウザー・同じURLの環境で復元します。
  端末やブラウザー間の同期は行いません。保存が使えない場合も画面操作は続けられます。
・設定のカテゴリ名を長押し（350ms）して、上下にドラッグする操作に変更しました。
  指を離すと自動で保存します。短いスワイプは通常のスクロールとして扱います。
  PCではマウスのドラッグ、キーボードではスペースキーと上下矢印で移動できます。
  保存に失敗した場合は共有設定の順序に戻し、再操作できます。
  新規追加時は先頭・末尾を選べます。初期選択は先頭です。
  順序は共有設定に保存し、設定画面・記録フォーム・ホームの絞り込みに反映します。
  カテゴリ別の集計グラフは、従来どおり金額順です。

ローカルでの画面確認（PowerShell）
  cd C:\Users\toshiki\date-wallet
  npm install
  npm run dev
  ターミナルに表示されるLocalのURLを開きます。終了はCtrl+Cです。
  現在の .env.local を使う起動では、データ保存先はそこに設定されたFirebaseです。
  ローカルで画面を起動することと、データ保存先をローカルにすることは別です。

画面で確認する操作
1. 設定を開き、カテゴリ名を長押しし、そのまま上下に動かして指を離します。
   ホームの絞り込みと記録フォームにも同じ順序が反映されます。
2. カテゴリを追加するときに「追加する位置」を選びます。
3. グラフを「全期間」にして再読み込みします。同じユーザーで再ログインしても復元します。
4. 共有相手が同時に編集した項目を古い画面から保存すると、再表示の案内が出ます。

確認していない範囲・反映時の条件
・実ブラウザーでの表示、スマートフォンでの長押し、実機を二台使った操作は未検証です。
・本番Firestoreの権限設定はリポジトリにありません。
  firestore.test.rulesは認証済みクライアント用のエミュレーター専用設定です。
  本番の参加者制限や権限を検証したものではなく、本番には配布・適用していません。
・本番反映の成否は、該当コミットのVercelチェックと公開URLで確認します。
・旧版のOFF設定は休止日を保存していないため、有効だった過去の期間を復元できません。
  この場合は架空の支出を避けるため、再開日より前の未計上分をすべて除外します。
・カテゴリ削除と記録作成の競合防止は、今回の版で記録更新時に共有設定の
  expenseRevisionを更新する仕組みを使います。旧版の画面が同時に書き込む場合は、
  この条件を満たしません。本番反映時には共有する利用者全員が今回の版を使う必要があります。
